AI郵報｜One Claude：Cowork、Chat、Docs、Slides 與 Design 合流

來源：AI郵報 Threads 與深度文章；核心產品事實以 Anthropic 官方公告〈Claude Cowork and chat are now one Claude〉（2026-09-16）交叉確認。

One Claude：從選工具，變成直接交付成果

Anthropic 將 Claude Cowork 與一般 Chat 整合成單一 Claude 體驗。使用者不必先判斷「這是聊天還是 agent 任務」：同一段對話可處理快速問答，也可將研究、資料整理、文件與簡報交付 Claude 在雲端繼續完成。

這不是把兩個入口改名而已，而是讓對話既有的 context、skills 與 connectors 能延伸到更大型的工作；原本 Cowork 的 chats、projects、artifacts、connectors 和 skills 也會保留。

官方已確認的能力

  • **Claude Docs**：從對話建立、共同編輯文件；可從同一個分享連結開啟與持續修改。
  • **Claude Slides**：從對話草擬投影片，可直接展示或下載 PowerPoint、PDF。
  • **Claude Design**：已可在對話中使用，仍可獨立使用。
  • **雲端非同步工作**：交付較大任務後，即使關閉筆電，Claude 仍可持續執行；使用者可從手機查看進度。
  • **Scheduled Work**：可將工作排程化，例如每週例行報告；官方示例是固定時間產出 pipeline report 與五頁管理簡報。
  • **Connectors 與既有上下文**：大型任務可使用同一對話裡的 context、skills、connectors；任何資料連接仍取決於使用者實際授權。
  • **人類仍有最後決定權**：預設 Claude 在採取 action 前詢問；使用者可選擇降低 check-in 頻率，但官方明確表示 final say 仍在使用者手上。

一分鐘理解實際工作流

你可以先問：「上週 pipeline 有什麼變化？」接著在同一對話補充：「照我們平常格式寫報告、標記延遲項目，並整理五頁主管會議投影片。」Claude 可基於同一脈絡產出 Docs 與 Slides；使用者編修其中一行、在 slide 留評論、下載 PPTX／PDF，或將這項報告排程為每週一執行。

關鍵價值是消除原本的「入口判斷」與「context 斷裂」：不是先選 Chat、Cowork 或 Design，再重新 briefing；而是從任務出發，讓 Claude 選擇需要的工作方式。

rollout 與可用性

官方公告：功能正於未來數週分批 rollout 給 Claude app 的 Pro／Max（Web、Desktop、Mobile）既有與新使用者；不需要額外開關。Docs、Slides、Design 在付費方案為 beta。Team 與 Free 隨後跟進；Enterprise 管理員至少會在變更前 30 天收到通知，且可選擇啟用時間。

因此不要將社群所稱的「現在全面可用」視為已發生的事。應以帳號中的 Claude app 提示為準，也應先確認你的 region、plan 與 organization policy。

對欒帥最有價值的使用方式

  • **每週 AI 學習雷達／研究摘要**：建立明確來源範圍與固定輸出格式，使用排程產出初稿；最終由人類查核、選題與發布。
  • **課程與會議材料**：把既有講稿、題綱、受眾與時間限制放在同一對話，要求 Claude 先做 Docs，再生成 Slides，並保留人工審稿與事實查核。
  • **跨文件決策包**：連接已獲授權的 Drive／Slack 資料後，讓 Claude 先整理證據、假設、未決問題，再製作文稿與簡報；不要直接要求它做最終商業或人事決策。

治理與風險提醒

  • **Connectors 是資料邊界，不是便利功能而已**：只連接任務所需資料夾／頻道；定期檢查 connector scope、可讀資料與分享設定。
  • **非同步不等於無需監督**：設定明確完成條件、預算、停止條件與每次 action 的人工核准層級。
  • **文件／簡報要查核**：語句通順、排版完整不等於數字、引用、權利與決策建議正確。對外發布前仍需負責人確認。
  • **排程任務需防 stale context**：每次交付應列出資料期間、來源、未取得資料與可能變動的假設，避免每週自動複製過期判斷。
  • **高風險動作維持人工核准**：付款、寄送正式外部訊息、存取敏感資料、刪除內容、部署 production 等不得僅因為 agent 能持續執行就自動化。

結論

One Claude 的真正改變是把 AI 從「輸出一段答案」推向「在同一脈絡中持續完成有形產物」。對個人工作流而言，它能明顯降低工具切換與重複交代背景的成本；對組織而言，成敗則取決於 connector 權限、產出審核與最終問責是否仍由人類掌握。

最好的原則：**讓 Claude 自動選擇工作方式，但讓人類明確決定資料範圍、行動權限與可接受的完成標準。**
