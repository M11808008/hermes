Facebook｜Marketing Agent：寄生既有 WordPress SEO 外掛需求，用 Claude Code 自動修站並收費

一句話摘要

這則貼文把 Marketing Agent 的機會講得很清楚：不是只做自動投廣告，而是找到既有工具裡已經被明確標出的痛點，接上 AI coding / content agent 自動修好，再用 agent 找客戶並完成成長閉環。

為什麼保存

這篇值得放進 AI 學習雷達，因為它展示的是「AI agent 商業化」很實際的一種切入方式：

  • 不從零教育市場，而是寄生在既有工具與既有工作流上。
  • 不只賣 AI 聊天，而是解決工具已經指出、使用者卻沒時間處理的任務。
  • 不只做產品功能，而是把找客戶、產素材、投放、回收數據與迭代都放進 Marketing Agent 閉環。

對欒帥正在累積的 agent / Hermes / AI 工具觀察來說，這是很好的「需求在哪裡被暴露，就在哪裡接 AI 自動修復」案例。

Facebook 貼文重點

作者貝克菜分享，自己聽了兩部一個多小時的 Podcast，內容在談 Marketing Agent：

  • 設定整套流程，讓 AI 自己抓熱度。
  • 自動產生素材。
  • 上到廣告平台投放。
  • 拉回數據、解讀數據。
  • 再次產生素材並迭代。
  • 最後形成可以自動運行的行銷閉環。

但作者真正注意到的不是整套運作細節，而是其中提到的機會與執行方式。

WordPress Yoast SEO Plugin 例子

貼文提到的例子是 WordPress Yoast SEO Plugin：

  • Yoast SEO 是大量 WordPress 網站會安裝的 SEO 外掛。
  • 站長每次登入 WP 後台，都會看到外掛提供 SEO 建議。
  • 這些建議會指出：網站哪裡 SEO 沒做好、哪篇文章可以補哪些細節與內容。

這裡的洞察是：Yoast 已經幫創業者把「未完成任務清單」標出來了。使用者不一定有時間或能力逐一處理，但需求已經在 UI 裡被明確呈現。

商業模式拆解

貼文描述的做法可以拆成四步：

  • **寄生既有工具**：鎖定已經很多人使用的 WordPress / Yoast SEO 生態。
  • **讀取問題**：做一個外掛專門讀取 Yoast 或後台指出的 SEO 問題。
  • **AI 自動修復**：呼叫 Claude Code 或類似 agent 產生修正內容、補細節、調整頁面。
  • **結果收費**：站長為「把已知問題自動修好」付費，而不是為抽象 AI 能力付費。

接著再用 Marketing Agent 找出正在使用 WordPress / Yoast 的人，把這個產品推給他們。

實務判讀

這個案例的重點不是 Yoast 本身，而是一種可複製的模式：

> 找到高普及率工具中已經被系統標記出的問題 → 用 AI agent 自動完成 → 向既有使用者收費 → 再用 agent 做成長。

可以套用到很多場景：

  • Shopify 商店後台的 SEO、轉換率與商品頁建議。
  • Google Search Console 的索引、排名與內容缺口提示。
  • HubSpot / CRM 中的銷售漏斗與客戶跟進缺口。
  • Notion / Airtable / Linear / GitHub 中長期堆積的待辦與 issue。
  • LMS / 教學平台中學生作業、回饋與教材補強需求。

只要某個平台已經有「問題清單」或「建議清單」，AI agent 就有機會成為自動執行層。

對 Hermes 的啟發

這則貼文也可以反推 Hermes / 個人 AI 助理的產品方向：

  • Hermes 不一定只做聊天入口，也可以讀取使用者既有工具裡的待辦、錯誤、建議與機會。
  • 真正有價值的是把「看見問題」變成「自動完成」的閉環。
  • 如果能同時處理執行、驗證、回報與後續追蹤，就更接近 agentic workflow，而不只是 automation script。

風險與限制

  • 貼文是對 Podcast 內容的心得轉述，細節仍需回到 Greg Isenberg 頻道與原始訪談查核。
  • WordPress 外掛若要自動修改內容，必須處理權限、備份、版本控制與回滾。
  • SEO 建議不一定都正確，尤其不同語言與市場會有落差；自動修復前仍需要品質門檻。
  • 若要讀取第三方外掛資料或後台資訊，需注意 WordPress 安全、資料隱私與外掛相容性。
