Threads｜Dustin GMAT：Mac mini M4 Pro 48GB 本地模型選型筆記

來源是 Dustin GMAT（@dustin_gmat）在 Threads 分享的一則本地模型實測心得。貼文重點不是正式 benchmark，而是一個 Mac mini M4 Pro 48GB 使用者在多日拉模型評比後，整理出的「本地 / API 混合任務分工」清單。

公開 Threads 內容

Threads 可見 canonical URL 為 `https://www.threads.com/@dustin_gmat/post/DbLplZhj85f`，頁面擷取時主串顯示約 11 次瀏覽。公開貼文摘要如下：

  • 在 Mac mini M4 Pro 48GB 上，可用性最高的本地模型是 `Qwen 3.6 35B A3B`；作者測得 prefill 約 137 tok/s、decode 約 50 tok/s，認為速度還在可忍受範圍。
  • 用途建議：單發任務、資料標記清洗、OCR、夜間排程、簡單 agent loop。
  • 寫作模型：作者主觀認為 `Ornith 35B` 最自然，速度與 Qwen3.6 35B A3B 相仿，因此列為備選。
  • 本地語音轉錄：純中文可用 `Qwen3-ASR`；中英混雜可用 `WhisperX`。
  • 若不涉及機敏隱私，圖像辨識、語音轉錄與資料標記清洗可交給 `Gemini Flash-Lite`，理由是便宜且適合雜活。

官方來源與查核

Qwen 方面，Brave 搜尋找到 Hugging Face 官方模型頁 `Qwen/Qwen3.6-35B-A3B`，模型頁與社群量化頁都確認 Qwen3.6-35B-A3B 存在；這支持貼文提到的模型名稱。貼文中的 prefill / decode 數字則是作者在 Mac mini M4 Pro 48GB 上的個人實測，不應視為官方或通用速度。

Ornith 方面，Hugging Face 上有 `deepreinforce-ai/Ornith-1.0-35B` 與 GGUF / MLX 版本；模型卡將 Ornith-1.0-35B 描述為 Ornith family 的 35B 輕量成員，並有 Apple Silicon / MLX 社群轉換版本。這支持「Ornith 35B 可作為本地模型選項」的說法；至於「寫作最自然」屬作者主觀評估。

語音轉錄方面，Qwen 官方 Hugging Face 與 GitHub `QwenLM/Qwen3-ASR` 顯示 Qwen3-ASR 有 0.6B / 1.7B 版本，支援語言識別、語音辨識、30 種語言與 22 種中文方言。這支持貼文把 Qwen3-ASR 放在中文轉錄選項。WhisperX 官方 GitHub 則將其定位為 automatic speech recognition with word-level timestamps and diarization，可用於轉錄與時間戳 / diarization 工作；這支持中英混雜或需要時間戳的本地 ASR pipeline 判讀。

Gemini Flash-Lite 方面，Google AI for Developers 的 Gemini API pricing 頁列出 Flash-Lite 為以成本效率、高 throughput 與品質為目標的低成本模型。這支持作者把 Gemini Flash-Lite 用於不敏感雜活的方向；但實際單價、免費額度、地區與速率限制仍需以 Google 最新價格頁與帳號方案為準。

實務判讀

這則貼文值得歸檔，因為它把「本地模型不是全包」講得很務實：

  • 本地 LLM 適合隱私敏感、可離線、可排程、成本可控的任務，例如資料清洗、批次標記、簡單 agent loop。
  • 寫作模型需要另行主觀評測；同樣大小與速度的模型，文字風格可能差很多。
  • ASR 要看語言組合與後處理需求：純中文可試 Qwen3-ASR；中英混雜、時間戳、說話者分離等工作流可考慮 WhisperX。
  • 雲端小模型仍有位置：不敏感、量大、便宜、需要吞吐的 OCR / 分類 / 標記 / 圖像理解，可以交給 Gemini Flash-Lite 這類 API，避免本地機器被雜活占滿。

對 Mac mini M4 Pro 48GB 這類桌面設備而言，關鍵不是追逐單一「最強模型」，而是建立任務路由：機敏資料優先本地；非機敏高吞吐雜活交給便宜 API；寫作與長文另測風格；語音依語言與時間戳需求拆工具。

補充邊界

  • 貼文速度數字是作者環境的個人測試；本地速度會受量化格式、runtime、context 長度、batch 設定、記憶體壓力、散熱與同時任務影響。
  • `Qwen3.6-35B-A3B`、`Ornith-1.0-35B` 等模型的授權、商用條款、衍生模型限制與安全設定需以各模型卡最新版為準。
  • OCR 與資料標記若含個資、財務、醫療、學生資料或商業機密，不應直接丟給雲端 API；需先做資料分級、去識別化與最小必要傳輸。
  • ASR 結果需人工抽樣校對；中英混雜、專有名詞、口音、多人會議都容易提高錯誤率。
