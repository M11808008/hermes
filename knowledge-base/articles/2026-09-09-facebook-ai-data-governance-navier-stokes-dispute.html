葉佰蒼以「一秒變駭客」為標題，表示自己雖然同時訂閱 OpenAI、Google 和 Claude，但公司商用內容只使用他稱為「負責任的 AI」的 Claude。

貼文提出幾個判斷：

  • OpenAI：作者質疑公司治理與「商業價值勝於安全」的取向。
  • Google：作者以 Chrome 無痕模式和 Gemini 記憶功能，提醒使用者不要把「不在畫面上顯示」誤認為「平台完全不知道」或「不會保留」。
  • Claude：作者把它當成公司商用工作的主要選擇。

這些是作者的立場和風險提醒，不是對三家公司目前所有方案、帳戶層級和資料設定的完整比較。

Navier–Stokes 研究爭議

貼文轉述一篇文章，內容涉及 NYU 數學教授 Tristan Buckmaster、Anthropic 數學家 Levent Alpöge，以及 OpenAI 對 Navier–Stokes 千禧年難題的研究競爭。貼文的說法是：

  • Buckmaster 與 Alpöge 使用 Codex 和 Claude 推進研究。
  • OpenAI 後來用未公開的下一代模型發表相關證明。
  • OpenAI 的研究路線被指與兩位研究者相近。
  • Buckmaster 認為，若平台掌握使用者完整工作痕跡，再用遠高於個人的算力競爭，便會產生公平性問題。

Facebook 貼文還寫到 3,000 億輸出 token、約 2,250 萬美元算力成本，以及 OpenAI 研究員對 Buckmaster 的回應。這些細節目前應視為貼文轉述，不能只靠 Facebook 文字確認。

外部報導查核

USA Today 2026-09-08 的報導確認：OpenAI 宣稱內部未公開模型解出 Navier–Stokes 相關問題；Buckmaster 則表示自己和 Alpöge 已投入約一年研究，並指控 OpenAI 可能在他們的成果公開前沿用了相近路線。報導也引述 OpenAI，稱研究者的說法「categorically false」，並表示在研究者公開前，OpenAI 研究者沒有透過任何方式看到他們的工作，尤其沒有存取特定使用者資料來解題。

TechCrunch 同日報導了三篇證明、Codex 與 Claude 的使用，以及 OpenAI 隨後公開相關證明的時間線；其報導也把「300 billion output tokens」和約 2,250 萬美元的估算寫成事件中的說法，但這不是獨立審計結果。

  • OpenAI 已經證實使用 Buckmaster 的私有 Codex 工作紀錄。
  • 3,000 億 token 和 2,250 萬美元就是實際、可稽核的成本。
  • OpenAI 一定是因為看到了研究者的資料才找到相同路線。
  • 所有 OpenAI、Google 或 Claude 帳戶都採用同一套資料訓練政策。
  • 使用 Claude 就代表公司資料天然安全，或完全不需要權限、保留與合規設定。

對企業導入 AI 的實際提醒

### 1. 先分清楚帳戶類型

個人消費者方案、團隊方案、企業方案、API、雲端代管模型，資料使用、保留、管理員權限和合約條件可能不同。不要用社群文章的單一句話概括整個平台。

### 2. 機密資料先做分級

研究草稿、未發表論文、原始碼、客戶資料、商業策略和個資，不應直接丟進未經核准的聊天工具。先定義哪些資料可以外部處理，哪些只能走企業租戶或內網模型。

### 3. 保存可稽核紀錄

對重要研究或商業決策，保存模型版本、提示詞、輸入檔案、輸出內容、時間戳、操作者和權限。這不只為了防止模型訓練爭議，也能釐清人類與模型各自做了什麼。

### 4. 把資料政策變成操作規則

不要只寫「請勿上傳機密資料」。應明確規定：哪些資料可用個人帳號、哪些必須使用 API 或企業租戶、是否允許記憶功能、多久刪除紀錄、誰可以匯出，以及發生資料事件時由誰處理。
