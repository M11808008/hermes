一句話摘要

這支 Reel 把 agent-build.md 描述為一份可拖進 Claude Code 的訪談式引導檔：它詢問名稱、口氣、使用者背景、任務範圍、成功標準與禁止事項，然後產出幾個 Markdown 檔案，作為一個「會記得你」的個人 AI 夥伴設定。這是值得借鏡的設計模式；但原始檔案與作者網站沒有在公開貼文中提供，不能把影片敘述當成已驗證的可安裝工具或功能規格。

  • 將 agent-build.md 放入 Claude Code 後輸入「Get started」，會開始逐題訪談。
  • 訪談約十題、約 10 至 20 分鐘；問題包括名稱、語氣、使用者背景、日常工作、責任範圍、成功標準與不可做的事。
  • 產物是描述個性、對使用者的認識、長期記憶與紅線的多個 Markdown 檔案。

Claude Code 能被第一方文件確認的範圍

Anthropic 的 Claude Code Overview 將 Claude Code 說明為可讀取程式碼庫、編輯檔案、執行命令，並整合開發工具的 agentic coding tool；可在終端機、IDE、桌面 app 與網頁等介面使用。官方文件同時將「Store instructions and memories」列為 Claude Code 的使用主題。

這支持「用文字檔提供長期指令與工作脈絡」是合理的方向，但不證實特定 agent-build.md 的問答流程、個人資料處理方式、記憶保留範圍、付費資格或安全性。尤其不應把「只負責記得」誤解為 Claude Code 天生不會改檔或執行命令：官方概述明確說明它具備編輯與執行能力，實際權限仍取決於所載入的檔案、設定、工具與每次授權。

值得採用的設計：設定檔應先回答什麼

即使不使用該來源檔，也可以用自己的 Markdown 設定建立可審閱的個人夥伴框架：

  • 身分與語氣：角色名稱、溝通風格、語言、何時要簡短或展開。
  • 工作範圍：可以協助的任務、不能代替人做的決策、明確的停止條件。
  • 成功標準：輸出格式、證據要求、完成前的查核步驟與回覆節奏。
  • 記憶規則：哪些長期偏好可保存、哪些內容不可保存、來源如何標記、如何修正或刪除。
  • 權限與紅線：讀取、草擬、修改、執行、寄送、付款、發布等動作的分級；高影響操作必須先呈現預覽並由人核准。

最小安全實作

  • 不要直接把未知來源的 Markdown 丟進具備檔案與命令權限的 Agent 後就照做。先用純文字檢視每一條指令，特別是任何 shell 指令、下載、登入、網路請求、資料上傳、設定修改或自動執行描述。
  • 將個資、帳密、API 金鑰、付款資料、完整日曆、私密對話與未公開文件排除在初版訪談之外；先以可替換的示例資料測試。
  • 將「記憶」存成可閱讀、可版本控制、可逐項刪除的文字檔，而不是不透明地累積。每次新增長期事實前，保留來源與人工確認。
  • 開啟任何寫檔或命令能力前，先在獨立測試資料夾試跑，並把自動執行、對外傳送、推送程式碼、修改系統設定設為人工核准點。
  • 若日後找到原始 agent-build.md，仍應先確認作者、版本、授權與完整內容；不要因社群宣稱「免費」就略過供應鏈與隱私檢查。

為什麼值得收進 AI 學習雷達

這支影片的價值不在於某個未取得的檔案，而在於把個人 Agent 的核心拆成可被審閱的設定：人格、任務邊界、記憶和紅線。比起一開始要求 Agent 無所不能，先把這四項寫清楚，更能降低越權、遺忘、錯誤承諾與不必要資料暴露的風險。
