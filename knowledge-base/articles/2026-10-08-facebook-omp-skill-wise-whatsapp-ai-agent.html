Facebook｜OMP 的 Skill-Wise：把 AI Agent 接入 WhatsApp 的協作構想與授權邊界

一句話摘要

這則 OMP 網路行銷玩家貼文介紹名為 Skill-Wise 的自製小工具，主張可把 AI Agent 接到 WhatsApp，供一對一對話或公司群組使用，並可設定「同事的指令需先由主管核准」。其最值得借鏡之處不是特定產品功能，而是把 AI 的工作入口放進既有通訊工具，同時保留人工授權關卡。

來源脈絡

Facebook 的公開預覽文字可確認下列作者主張：

  • 工具名稱為 Skill-Wise。
  • AI Agent 可連接至 WhatsApp。
  • 可進行一對一對話，也可加入公司 WhatsApp 群組。
  • 同事可標記 AI 來查資料、做事。
  • 指令可以設定為先經管理者批准。

可以怎麼理解這個流程

  • 訊息入口：把 WhatsApp 當作同仁提出問題或任務的介面。
  • 指派方式：在群組中以標記方式呼叫 Agent，而非另開一套工作平台。
  • 執行前管控：將同事提出的任務置入核准流程；主管可在外部動作、資料查詢或回覆前把關。
  • 稽核設計：保留誰提出、誰核准、Agent 做了什麼、實際回覆什麼的紀錄，才能成為可管理的企業工作流。

已查核與未查核的範圍

Meta 的 WhatsApp Cloud API 文件證實 WhatsApp 提供商業訊息 API 平台；這不等於 Meta 官方背書或提供 Skill-Wise。貼文中的 Skill-Wise 名稱、實作、可用帳號類型、資料存取範圍、價格、是否公開提供、核准機制的實際技術做法，都僅能視為作者的社群介紹，尚未取得可獨立查核的產品文件。

導入檢核表

  • 確認使用的是公司核准的 WhatsApp Business／Cloud API 帳號與號碼，不以個人帳號承載敏感工作資料。
  • 對 Agent 設定最小權限：先讀取必要資料，再決定是否允許寫入、傳送或呼叫外部系統。
  • 將「查詢草稿」與「對外傳訊、建立訂單、修改資料」分級；後者應要求明確人工核准。
  • 記錄請求者、核准者、工具呼叫、輸出與失敗事件，並設定保存期限。
  • 不要將密碼、OTP、付款資訊、客戶個資或長效 access token 直接貼入群組或交給未經審核的第三方 Bot。
