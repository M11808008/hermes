AI郵報｜WSL Containers：替 Windows 上的 AI Agent 建立可重現、可驗證的 Linux 執行環境

一句話摘要

WSL Containers 讓 Windows 團隊能以 Linux 容器承載 Agent 的工具鏈與依賴；最佳實務不是只把 Agent 丟進容器，而是把映像版本、掛載範圍、網路／GPU 權限、任務輸入與可驗證輸出一併納入執行紀錄。

官方已確認的內容

Microsoft Learn 的 WSL container 文件說明：

  • WSL container 功能包含內建命令列工具 `wslc.exe`，用於建立、執行與互動 Linux 容器。
  • 也提供 WSL container API，讓 Windows 應用程式在自身邏輯中使用 Linux 容器。
  • 使用前要求 WSL 版本為 2.9.3 或以上；可透過 `wsl --update` 更新，以 `wsl --version` 查看目前版本。
  • API 可處理 stdin／stdout、檔案掛載、網路、GPU 存取等互動。
  • `Microsoft.WSL.Containers` NuGet 套件提供 C# 投影與 C++/WinRT 標頭；其中 C++/WinRT 投影仍標示為 preview，可能有破壞性變更。

為什麼對 AI Agent 有用

Agent 寫程式或跑資料流程時，常把時間耗在「缺少套件、版本不合、工具只支援 Linux、每台電腦環境不同」。把語言執行環境、系統依賴和特定工具鎖進映像，可讓每次任務從較一致的基準開始。

但可重現不是只記下 `ubuntu:latest`。真正需要記錄的是：

  • 基底映像的不可變版本或 digest。
  • 套件清單與工具版本。
  • 啟動命令、環境變數和 Agent 使用的任務指令。
  • 掛載的輸入與輸出目錄。
  • 是否開放網路、GPU 與其他設備。
  • 實際輸出、測試結果與失敗紀錄。

最小可行的 Agent 容器設計

### 1. 一種任務，一個明確輸入／輸出契約

先選擇可驗證的小任務，例如把 CSV 轉換為指定 JSON schema、執行測試套件，或生成固定格式報告。明確定義輸入檔、預期輸出目錄與驗收條件，而不是一開始就把整個專案交給 Agent 自由操作。

### 2. 將掛載視為資料權限

容器不會自動知道哪些檔案應可讀寫。建議把輸入以唯讀方式掛載，將產物寫到獨立輸出目錄；不要為了方便把整個使用者家目錄、憑證或所有專案資料夾都掛進去。

### 3. 網路與 GPU 採最小開放

離線轉檔通常不需要網路；需要下載模型或查詢 API 的任務則應記錄來源與取得時間。GPU 也不是「API 支援」就保證可用，仍要驗證主機、驅動、模型大小與併發負載。

### 4. 用測試與產物驗證取代「退出碼為 0」

零結束碼只代表程序正常結束，不代表資料沒漏、程式修正正確或報告內容合格。交付前至少檢查：輸出檔是否存在、筆數／schema 是否符合、測試是否通過，以及產物是否位於指定目錄。

可直接採用的執行紀錄模板

  • 任務 ID 與執行時間
  • 映像名稱、tag 與 digest
  • WSL／`wslc`／工具版本
  • Agent 指令與使用的任務描述版本
  • 唯讀輸入掛載、可寫輸出掛載
  • 網路、GPU、環境變數與資源限制
  • 程序退出碼、stderr 摘要
  • 產物路徑與驗收結果
  • 核准人或人工覆核結果

這份紀錄能把「Agent 說做完了」轉成後續人員能重跑、定位和覆核的工程證據。

試做路線

  • 先執行 `wsl --version`；若未達 2.9.3，先依官方文件更新。
  • 建立只含任務所需工具的小型映像，鎖定重要版本，不使用無版本控制的 `latest` 作為唯一依據。
  • 以獨立的 `input/`、`output/`、`logs/` 目錄進行第一個任務。
  • 加入一個已知失敗案例，例如缺少欄位或無法存取輸入，確認 Agent 是否留下正確失敗狀態而非偽造完成。
  • 比較多次重跑的輸出與準備時間，再決定是否擴大至更高風險的建置、部署或模型工作。

查核與限制

  • AI郵報原文對 Windows Agent 執行環境的工程分析，已以 Microsoft Learn 的 WSL container 官方文件核對核心功能與 WSL 2.9.3 最低版本要求。
  • `wslc.exe` 的存在、容器 API，以及檔案掛載、網路與 GPU 互動均有官方文件依據。
  • C++/WinRT 投影仍是 preview；不可把整個 WSL Containers 生態一概視為每個 API 都同等穩定。
  • 容器能改善一致性與控制面，不能自動提供完整安全隔離、保證 Agent 程式正確，或取代輸入／輸出驗證與權限治理。
  • 原文提及的 `wslc compose` 為規劃性資訊；官方目前文件未列出 compose 命令，故不作為已可用功能歸檔。
